## Rules

- **Template rule.** Every variable in the app, build, mobile or operator-scripts tier is declared exactly once in .env.example or mobile/.env.example, unless the platform supplies it. Tests-only and CI-only variables are listed here and need no template line; the few a developer sets by hand to run the e2e suite locally are also in the test-only block of .env.example.
- **Secret grade.** Secret-grade when the name matches /(SECRET|TOKEN|PASSWORD|PRIVATE_KEY|API_KEY|SERVICE_ROLE_KEY|_DB_URL$|^GOOGLE_SEARCH_CONSOLE_KEY$|^SYNC_TOKEN_KEY$)/ (except NEXT_PUBLIC_*/EXPO_PUBLIC_* and file-path names), or when a read is passed to configuredSecret/secretEquals/timingSafeEqual/createHmac/safeEqual. A workflow binding from secrets.* is recorded (boundFromWorkflowSecret) but does not by itself make a name secret-grade: CI also stores public keys and project refs as secrets. A secret-grade name in .env.example carries a [secret] tag in its comment.
- **What counts as a read.** process.env.X, process.env["X"], const { X } = process.env, an alias initialised from process.env (or a parameter named env indexed by a computed key) read as alias.X, string literals listed in a file that indexes process.env by a computed key (e.g. credentialEnv in lib/social/capabilities.ts), and env: bindings in workflows. Assignments, delete and vi.stubEnv count as sets, not reads. Comments and strings never count.
- **Facts.** fallback-literal / fallback-variable / fallback-expression: what follows ?? or || at the read. compared-with: a literal the value is compared with. passed-to: the call the value is handed to. validated-by-regex: a regex .test() on the variable the value is stored in, within the same function.
- **Not scanned.** Shell, Python and SQL files; mobile/app.json extra (a fallback for EXPO_PUBLIC_*); vercel.json; Supabase config.
- **Platform-supplied** (no template line required): `NODE_ENV`, `NEXT_RUNTIME`, `NEXT_PHASE`, `VERCEL`, `VERCEL_ENV`, `VERCEL_URL`, `VERCEL_REGION`, `VERCEL_GIT_COMMIT_SHA`, `NEXT_PUBLIC_VERCEL_GIT_COMMIT_SHA`, `CI`, `GITHUB_ACTIONS`, `GITHUB_ENV`, `GITHUB_OUTPUT`, `GITHUB_STEP_SUMMARY`, `GITHUB_WORKSPACE`, `GITHUB_SHA`, `GITHUB_REF`, `GITHUB_REPOSITORY`, `GITHUB_EVENT_NAME`, `GITHUB_RUN_ID`, `GITHUB_RUN_ATTEMPT`, `GITHUB_JOB`, `GITHUB_WORKFLOW`, `GITHUB_API_URL`, `GITHUB_EVENT_PATH`, `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `RUNNER_TEMP`, `PATH`, `HOME`, `TZ`, `LANG`, `TMPDIR`, `USER`, `SHELL`, `npm_lifecycle_event`, `npm_config_user_agent`, `VITEST`, `VITEST_WORKER_ID`, `VITEST_POOL_ID`, `TEST_WORKER_INDEX`.

Tiers:

- `app`: read by app/, lib/, components/, middleware.ts or instrumentation.ts.
- `build`: read by next.config.mjs or capacitor.config.ts at build time.
- `mobile`: read by the Expo app under mobile/src (EXPO_PUBLIC_* values are inlined at build).
- `operator-scripts`: read by scripts/ that a person runs by hand (and possibly by tests), and not bound by any workflow.
- `ci-scripts`: read by scripts/ and also bound by a .github/workflows env: block or read by a scripts/ci-*.mjs file: CI plumbing an operator may also set.
- `ci-only`: bound only by a .github/workflows env: block (and possibly read by tests).
- `tests-only`: read only by tests/ or the test-runner configs.
- `set-but-never-read`: only set by tests (process.env.X = …, vi.stubEnv) or only declared in a template; no scanned code reads it.
