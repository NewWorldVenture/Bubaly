# DATA-007 — checked capture persistence and caller outcomes

Source work began after reading the recorded DATA-007 and `quick-capture-discovery-cycle.md`. Root authorized the helper and focused tests, then the bounded voice consumer compatibility repair. No SQL, dependencies, shared navigation or master audit edits belong to this lane.

Before the voice source edit, inspection confirmed `components/modules/voice-module.tsx` uses a render-state-only busy check, invokes the client factory outside its try block, omits the helper lifetime guard, and treats every save exception as a definite failed command. Its catch also writes a failed history row even when the capture mutation may already have committed. Retrying the same command after an unconfirmed write can create another row. Owner changes during the required list lookup can permit a retired operation to dispatch the later item write. These are the specific compatibility defects this caller patch addresses; microphone/provider and voice-history management workflows remain outside the patch.

The additive helper contract is `CaptureSaveInput.isCurrent?: () => boolean`, exported `CaptureSaveError` with `outcome: failed | uncertain | retired`, `stage: lookup | list | capture | undo`, destination `href`, and cumulative `dispatched`. Definitive database errors retain their original message, code and cause. Save success keeps its original result shape and adds optional `undo.familyId`; Undo accepts an optional third operation guard. New Undo descriptors always contain the validated receipt IDs and family scope.

Required list reads now distinguish confirmed empty data from errors. Both task and shopping list creation must return a valid ID before item insertion. Every capture/Undo write requires the expected number of distinct UUID receipts; Undo additionally requires the exact requested identity set. Missing, malformed, truncated or duplicate write receipts and transport/representation failures are uncertain, and no helper retry is attempted. A PostgreSQL statement rejection is distinct from uncertainty. The caller guard is checked before requests and after awaited prerequisites. Existing member-ID foreign-key attribution and nullable optional member behavior are preserved.

The initial focused installed-SDK transport run reproduced the unchecked branches. Its first version also encountered the SDK's automatic GET transport retry timeout and an array-case parameterization mistake; these fixture limitations were corrected before judging the regression results. Final helper coverage contains **62 passing tests**: 11 existing parsing/payload tests upgraded to meaningful UUID receipts and 51 installed-SDK boundary cases. These include required-read failures, valid empty lookup, list-create failure/uncertainty, member attribution, retired operations between every prerequisite stage, exact mutation receipts, explicit error/cause preservation, checked deletion, and deadlines.

QuickCapture and CaptureShell consumer changes belong to the UI agent. CommandBar is deliberately untouched under the shared-navigation constraint: it still lacks the optional lifetime guard and treats uncertain results as ordinary retryable errors. Therefore this lane does not claim every capture consumer is complete. Explicit user-triggered earlier-family Undo remains permitted by root; the helper scopes it to the family and exact saved IDs without substituting the currently displayed family.

Root's independent review identified a required deadline follow-up before its implementation: the helper awaited SDK requests without a bound, while the repaired QuickCapture intentionally disables close paths during a pending write. A stalled list read or POST could therefore hold that form indefinitely. Three installed-SDK/fake-clock probes were explicitly red: held lookup, held mutation and a transport ignoring abort all remained pending after 15 seconds. The repair now passes an actual abort signal to every SDK query and enforces a 15-second request deadline. Lookup timeout is failed; dispatched mutation timeout is uncertain. A late acknowledgement cannot resolve Saved. The deadline also settles the caller if an injected transport ignores abort; the underlying query promise remains handled. The actual abort uses `AbortError`, because the installed SDK retried a `TimeoutError`-named GET failure even after its signal was aborted. The final probes require exactly one request and an aborted signal. No global SDK transport or mutation retry was introduced.

A related voice continuation was reproduced before its correction: after a confirmed task insert, a held `voice_commands` history POST kept the input disabled and withheld success/Undo indefinitely. The actual browser assertion failed on that retained draft. Since the existing source explicitly defines this history write as best-effort, the caller now dispatches it without awaiting it and handles both promise outcomes; confirmed capture feedback and definite failure feedback no longer depend on optional history availability.

## Voice execution and final verification

`tests/e2e/voice-capture-boundaries.spec.ts` executes the actual VoiceModule, capture helper/parsers/router and installed React/Supabase SDK in Chromium. Speech recognition, AppContext, history subscription and presentation primitives are isolated; this proves typed-command persistence/lifetime behavior, not microphone capture, authenticated AppProvider behavior, hosted RLS or live speech/provider delivery. The transport records mutations and retains stored items, including a persisted item whose returned ID receipt is deliberately empty.

The voice component keys its capture session by family/user, checks a synchronous operation lock, retires callbacks on unmount, passes the current-operation guard to the helper, and holds uncertain commands with a translated destination-review link. It never writes a definitive failed-command history entry for an uncertain save. Earlier-family Undo remains an explicit user action, scoped by captured family and IDs, with one pending attempt and no blind repeat after an uncertain delete.
