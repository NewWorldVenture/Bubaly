# Independent rewards readback review

This review examined root's additive query-confirmation integration in `components/modules/rewards-module.tsx` and the existing actual-component regressions in `tests/e2e/rewards-ledger.spec.ts`. The UI review lane did not edit rewards production source or the shared query hook.

The uniquely owned `tests/e2e/rewards-readback-review.spec.ts` executes the actual RewardsModule, React, query hook, authenticated cache boundary, ledger math, shared controls, and installed Supabase/PostgREST SDK with controlled auth/realtime and persisted transport. It derives from the existing fixture; translation is a flat-message boundary in this fixture, so this cycle does not claim locale-provider coverage. No hosted database, provider, or SQL behavior is asserted.

The initial five-case independent run had four positive controls and one genuine failed regression. Repeated failed retries did not repeat a durable create or success callback; retiring the actual access boundary discarded deferred completion; an uncommitted failed write preserved its draft and did not acquire a deferred success; and a superseding catalog readback error did not unlock completion before retry. However, a retained new-reward submit callback could run after successful deferred completion had closed its form. The actual sequence was: capture React onSubmit, POST succeeds, catalog readback fails, Retry confirms and closes the form, invoke the old onSubmit. The fixture persisted a second identical reward, so expected one row received two. This is controlled retained-callback evidence; it does not claim ordinary navigation spontaneously emits that callback.

Root recorded and repaired the issue with a per-opening form epoch, checked by save and retired on close/completion. Checking only whether some modal is open would not protect a newly opened form from an old callback. The permanent review adds both reopening and canceled/reopened regressions and confirms that the new current form can still submit deliberately.

Final result: **7 independent review cases passed**, as part of the focused **37-case run in 5.4 seconds** comprising these seven plus 30 hydration cases. Scoped lint and whitespace checks passed. Root separately owns the existing 23-case rewards run and its broader evidence. No remaining false unlock, repeated deferred completion, failed-write draft regression, or owner-retirement regression was reproduced in this bounded review.

The retained-form finding also prompted the documented hydration self-review and minimal modal-lifetime repair in `hydration-ledger-cycle.md`. These local UI guards and confirmed readbacks do not establish atomic database enforcement or protection for arbitrary direct-client mutations. Full-project type/build/release verification remains root-owned.
