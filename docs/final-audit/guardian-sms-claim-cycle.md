`claimGuardianSms(client, eventId, signal?)` verifies the inserted representation before returning `{kind:'claimed', lease:{eventId,token}}`. A duplicate requires an exact same-event read and `inbound_sms` callback type. Only a valid processed timestamp returns `processed`; fresh processing returns `busy`. An error can be reclaimed immediately; processing must be strictly older than ten minutes. Reclaim filters the exact prior event, type, status, received timestamp and error, then verifies the new random `sms-lease:<UUID>` marker. Empty competing updates return busy. Required errors and malformed representations return unavailable.

`finishGuardianSms` and `releaseGuardianSms` update only the matching processing lease, verify the returned row and report a boolean result. A retired worker cannot complete or release a newer owner. Release leaves an error state available for immediate retry; it does not authorize replaying external sends. Each database request is limited to five seconds with an AbortError, optional caller cancellation and SDK retries disabled. The helper also stops awaiting a custom transport that ignores cancellation; a late database write remains possible and is handled conservatively as an unavailable receipt. These are per-query deadlines, not a whole-route deadline.

## Remaining delivery limits

A historical `processed` receipt cannot prove that the old route saved a communication correctly; this helper does not reconstruct previously lost messages. It also cannot force another provider callback after a process crashes. Twilio's default retry policy is `ct` for connection failures, with HTTP 5xx retry requiring the corresponding `rp` override; default read timeout and total request budget are each 15 seconds. HTTP 503 therefore does not guarantee provider redelivery, and deployed retry configuration was not inspected. [Twilio webhook connection overrides](https://www.twilio.com/docs/usage/webhooks/webhooks-connection-overrides).

At this checkpoint, the Guardian route performed synchronous decision/AI work before persisting the message. Source `237933c1` now retains verified pending intake first; see [policy and retention verification](guardian-policy-read-checkpoint.md). Classification and the ten-minute lease can still exceed the provider request window. Independent recovery remains a follow-up; truthful failures, pending storage and lease fencing are not a complete durable handoff. Family notification uniqueness and external push/SMS delivery are separate from callback-row ownership, and acceptance is not handset receipt.

The earlier independent review identified contact/profile read errors and rules-read fallback in the shared pipeline. Those required reads are repaired by `237933c1` and now execute through the real pipeline in signed SMS fixtures. The scope and notification service query deadlines remain separate concerns. A later review also identified stored decision-authorship risk under authenticated communication inserts; `AUTHZ-004` records its exact prerequisites and required receipt binding. Scoped receipt validation and callback lease checks do not establish that broader authorization property.
