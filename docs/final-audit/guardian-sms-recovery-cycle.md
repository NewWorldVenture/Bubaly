# Guardian SMS autonomous recovery

Baseline: `0b1906593adee286e59a8330311e74ad43cdfef4`. Audit ID: SMS-002. Status: IN PROGRESS. Severity: High.

A signed SMS can be retained as a neutral communication with a captured service receipt and an error callback after a required policy or screening operation fails. The existing execution test reproduces that state, but completing it requires another provider callback. No background consumer currently reads Guardian intake receipts.

The repair will add a bounded scheduled consumer of service-owned intake receipts and share the authenticated processing path with the webhook. It must never reconstruct authority from member-writable communications. Current destination ownership, exact payload and communication identity, and the callback lease remain required. Saved decisions remain immutable.

Completion will be recorded only after the exact communication, any required notification and the processed callback are verified. A processed callback without a terminal receipt permits read-only completion reconciliation, not a new classification or notification. Legacy captured and decided receipts remain recoverable. A durable cursor must advance past malformed, busy or failing rows so one item cannot starve later messages. Retry delays must not replace eventual recovery.

Verification will reproduce recovery without a second provider call; exercise capture, decision, notification and completion failures; verify concurrent workers, ownership changes, malformed receipts, poison-row traversal, lost responses and cancellation; and test cron authorization and schedule parity. Existing signed ingress, policy, lease, receipt and notification regressions remain required. Hosted PostgreSQL and HTTP acceptance will follow focused checks and a frozen production build.

No SQL, dependency installation, shared navigation changes or live outbound messages are part of this cycle. Provider delivery and production scheduler configuration remain separate verification obligations. Cross-table operations are not transactions.

The implementation now shares processing between signed ingress and recovery. The worker scans captured and decided receipts, reserves a durable cursor position before each attempt, and advances past failing or busy work. Cursor revisions prevent competing jobs from overwriting another job's progress. Individual requests, processing attempts and the whole job have deadlines. Completed receipts are excluded from the scan.

Notifications use a deterministic primary key with exact content readback, while retaining the family's quiet-hour behavior and accepting a single verified legacy notification. Completion independently checks the communication, required notification and processed callback. Review reproduced a retry trap when a destination disappeared temporarily; the repaired route acknowledges an unknown destination only after verifying that no trusted receipt is retained for that SID.
