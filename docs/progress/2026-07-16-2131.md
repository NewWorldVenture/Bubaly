## Finding (PLA-0461 / LB-009, P1 — OPEN, owner-gated)

While auditing the A-11 messages/media sub-surface I found that the **`family-media` Storage bucket is defined in no migration**, yet four features upload to it — Photos (`photos-module`), Create-Memory (`create-memory`), Messages attachments (`messages-module`), Reminder attachments (`reminders-module`) — via `lib/storage/family-media.ts`. It exists in production only because it was created manually in the Supabase dashboard.

Two problems:
1. **Reproducibility / wiring gap** — every other bucket is created in a migration (`documents` 0007, `chore-proof` 0043, `avatars` 0089, `marketplace-photos` 0194, `marketing-assets` 0060, feedback 0197). `family-media` is not, so a fresh Supabase project or the PG16 harness has **no bucket** and all four upload flows fail; the bucket's `public` flag + RLS live only in the dashboard, outside version control.
2. **Privacy** — all four consumers resolve attachments with `getPublicUrl` (public-read bucket). Paths are `${familyId}/…/${Date.now()}.${ext}` (semi-guessable), so family photos (incl. children's), private message image/audio/file attachments, and memories are **readable by URL without auth, bypassing family RLS**. The `documents` bucket (private + signed URLs, verified in PLA-0442) is the correct contrast.

**Why documented, not shipped:** the fix is a **prod storage migration** (human-owned per the coordination rules) plus a **public→private security/UX decision** that switches four modules from `getPublicUrl` to `createSignedUrl` — architecturally significant and cross-module. Recorded as **LB-009** + **PLA-0461** with a two-step recommended fix, flagged to the owner.

## Recommended fix (owner-gated)

1. Idempotent migration creating `family-media` (`insert … on conflict do nothing`, 25 MB limit) + family-folder **write** RLS on `storage.objects` (`is_family_member(((storage.foldername(name))[1])::uuid)`), mirroring the `documents` bucket — fixes fresh envs + blocks cross-family writes without altering the existing prod bucket.
2. Decide read visibility: private bucket + family-folder SELECT policy + switch the four consumers to `createSignedUrl` (the `documents-module` pattern) to close the public-read privacy gap.
