## Completed Increment

- **PLA-0409 (P1)** — Fixed silent data loss in the **Home module CRUD**. Six `void`-returning form actions (`saveWarrantyAction`, `deleteWarrantyAction`, `saveContractorAction`, `deleteContractorAction`, `saveServiceRecordAction`, `deleteServiceRecordAction`) discarded the write result, then called `revalidatePath` and returned normally — so on any write failure (RLS, constraint, outage) the modal closed and the page refreshed as if the save had succeeded while the record was never persisted. Now every write captures `{ error }` and throws `describeActionError(...)` on failure (the idiom already used in `social`/`kitchen`/`trip-intel` actions), so the client transition rejects, the modal stays open, and the failure is surfaced. The best-effort `home_assets.last_serviced_on` refresh now logs instead of throwing. Added `tests/home-actions-write-boundary.test.ts`.
